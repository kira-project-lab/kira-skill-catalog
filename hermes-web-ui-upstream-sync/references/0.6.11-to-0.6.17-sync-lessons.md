# 0.6.11 → 0.6.17 upstream sync lessons

Context: Kira Hermes Web UI was at `0.6.11`; upstream author branch was `0.6.17`. A first integration branch was created from `upstream/main` and Kira `origin/dev` was merged/reconciled on top. Build and harness passed, but full tests stayed red, so the branch was not merge-ready.

## Durable lessons

- A branch-from-upstream strategy is correct for large drift, but it must be followed by **layer commits**, not one large merge commit. One large merge made it harder to isolate whether failures came from bridge, session DB, coding-agent policy, or stale tests.
- Do not treat `npm run build` as a meaningful green gate for upstream sync. In this case build passed while many runtime/contract tests still failed.
- If unit tests are red, do **not** deploy to live-dev or branch preview for browser QA. First stabilize local contract tests; otherwise browser QA will mask known broken contracts.
- For broad chat/session/runtime syncs, run targeted test shards after each layer and only then run full `npm run test`, `test:coverage`, and `test:e2e`.

## Reconciliation hotspots found

- `packages/server/src/services/hermes/run-chat/session-command.ts`
  - Upstream introduced branch/fork/reload-skills behavior.
  - Kira had downstream policy such as `/yolo` routing.
  - Correct repair pattern: start from upstream command parser, then re-add Kira commands as explicit additive cases with tests; do not restore the whole old Kira file.

- `packages/server/src/services/hermes/run-chat/handle-coding-agent-run.ts`
  - Upstream changed coding-agent launch/input contracts.
  - Kira tests expected older details such as passing system prompt/session source through old APIs.
  - Correct repair pattern: preserve upstream API shape first, then re-express Kira prompt/profile/session-source expectations at the new boundary or update stale tests if the implementation detail intentionally moved.

- `packages/server/src/services/coding-agents.ts`
  - Upstream contained desktop/runtime/windows/path fixes.
  - Restoring old Kira code risks losing those fixes.
  - Correct repair pattern: keep upstream baseline, then re-add only Kira-specific Codex profile OAuth/global-default policy with focused tests.

- `packages/server/src/services/hermes/agent-bridge/*`
  - Upstream moved to a newer Python bridge structure.
  - Kira had profile env inheritance expectations.
  - Correct repair pattern: port Kira env/profile contract into the new bridge structure; do not revive removed legacy bridge files.

- `packages/server/src/db/hermes/*session*` and session tests
  - Kira state DB/session overlays can fail in suite context if tables are not initialized exactly like production.
  - Correct repair pattern: validate initialization path and test fixtures separately before changing app behavior.

## Better next-pass sequence

1. Start `integration/upstream-<version>` from `upstream/main`.
2. Apply and commit deploy/topology only; run `harness:check`.
3. Apply Paperclip only; run focused server/client tests for Paperclip if present.
4. Apply bridge/runtime policy; run bridge/profile-env and run-chat tests.
5. Apply coding-agent Kira policy; run coding-agent tests.
6. Apply chat/session contracts; run session-command/session-store/session-controller tests.
7. Apply visual UX; run build and relevant client tests.
8. Only after full `npm run test` is green, run `test:coverage`, `test:e2e`, then preview/live-dev browser QA.

## Blocker-removal lessons from execution

- Treat the first full-test run as a blocker inventory, then fix one layer at a time. In the 0.6.17 branch, the first high-leverage batch was server/runtime, not UI: `/yolo` command parsing, bridge-broker routing, profile env application, auxiliary LLM broker routing, and process-exit error formatting.
- When upstream moves Python bridge behavior into `python/bridge_broker.py` / `python/bridge_runtime.py`, port Kira behavior there instead of patching only the TypeScript bridge client. For Kira `/yolo`, the durable path is: session command parser accepts `/yolo` → TypeScript bridge client sends `yolo_toggle` → Python broker handles `yolo_toggle` for the profile worker.
- For profile-scoped bridge tests, the key contract is that requested profile `HERMES_HOME` / profile `.env` is applied inside the worker context and restored afterward. Do not satisfy the test by changing expected homes to the root bridge home.
- For `auxiliary_llm`, broker-level forwarding to the profile worker is a real runtime contract, not a stale test. Keep it near other broker action routing.
- `formatCodingAgentProcessExitError` is a public testable helper for readable coding-agent failures. If upstream refactors error handling, keep a narrow exported adapter rather than changing the runtime manager's broader failure behavior.
- Before broad generated edits such as merging upstream locale keys into every locale file, stop and present the exact file set / strategy. Use targeted skill/file edits where possible; do not hide a large generated rewrite inside a shell one-liner during blocker removal.
- After repairing the first runtime layer, run the full `tests/server` shard before moving to client/UI. In this sync, useful server-stabilization fixes included: forwarding `sessionSource: global_agent` through `handle-coding-agent-run`, preserving it during bridge resume, adapting stale initial-title tests away from removed `handle-api-run.ts`, and keeping upstream Claude Code prompt-file launch args in tests rather than removing them.
- When upstream adds Claude Code `--append-system-prompt-file` / managed `hermes-rules.md`, treat old tests expecting no prompt file as stale unless the product contract explicitly forbids prompt injection. Preserve upstream prompt-file behavior and update tests to assert the new prompt file path/content.
- Kira global Codex OAuth policy can coexist with upstream 0.6.17 launch changes by adding a narrow `maybePrepareGlobalCodexHome()` path for `mode: global` + `codex`: copy selected-profile `openai-codex` auth tokens into an isolated `CODEX_HOME`, write `config.toml` with the downstream default model, and leave global Claude Code behavior on upstream's prompt-file path.
- Full-suite failures after server is green may be mostly client/stale-contract work, not runtime regressions. Typical 0.6.17 leftovers: mocks missing new API exports such as `getApiKey`/`getBaseUrlValue`/`fetchSessionsPage`, source-text tests still expecting removed DOM/classes, PWA manifest path drift (`site.webmanifest` vs old `manifest.webmanifest`), and large i18n coverage gaps from upstream locale keys.
- For Playwright tests that mock `socket.io-client`, include the manager surface as well as socket events. Newer client code may call `socket.io.on('reconnect', ...)`; a mock that only implements `socket.on(...)` can crash the whole app into a blank page. Fix the fixture with `socket.io.on()` / manager listener support before changing app code.
- For upstream-sync e2e failures, inspect screenshots/traces to separate real regressions from stale selectors. Examples from 0.6.17: group chat title moved to `.header-session-title`/message evidence, voice recording swaps the mic toggle for cancel/confirm controls while active, and session rows legitimately reserve avatar/date width even when hidden action buttons are gone.
- If `npm run build` fails with `ChatRunSource` typing around resumed/reattached bridge runs, normalize raw DB/session strings through `resolveRunSource(...)` before passing them to typed run handlers instead of widening the handler type.
- For Node-only source-text contract tests, remove `// @vitest-environment jsdom` if they import `fs`; otherwise Vite can externalize `fs` for browser compatibility and fail with `readFileSync is not a function`.
- Branch-preview deploy can fail when the integration branch is checked out in another worktree. Push a short-lived mirror branch such as `preview/upstream-<version>` at the same commit and deploy that preview branch instead of force-switching the active integration worktree.
- Browser QA after green local gates still needs valid live-dev credentials. If the default login hint is stale and returns 401, report live browser QA as blocked on credentials/reset; do not claim completion from health + Playwright alone.

## Reporting rule

If any required validation gate fails, report the branch as a prepared baseline or repair branch, not as an upstream sync completion. Explicitly say merge to `origin/dev` is blocked until tests are green.
